(`Tests/`). Плагин и UI зависят от ядра, но не наоборот.

## Модель данных: параметры — единственный источник истины

* Все параметры описаны X-macro `TSL_PARAM_LIST` в `Source/Audio/Params.h` (261 параметр). Индекс — ID хоста
  (только добавление в конец), строковый ключ — для пресетов и состояния (ADR-007).
* UI не хранит копий DSP-состояния: контролы читают и пишут параметры плагина; изменения от хоста,
  автоматизации, MIDI и пресетов приходят в UI через `OnParamChangeUI` → `UIContext::notify`.
* Не-параметрическое состояние (порядок цепочки, параллельная секция, пути пользовательских IR, привязки MIDI,
  имя/ID пресета) хранится в классе плагина и сериализуется вместе с параметрами.

### Формат состояния (chunk)
Магическое число `TMSL`, версия, затем: параметры как пары `key → value`, порядок цепочки (ключи модулей),
пути IR слотов A/B, конфигурация параллельной секции, имя и ID пресета, MIDI-привязки. Неизвестные ключи
игнорируются, отсутствующие получают значения по умолчанию — проекты, сохранённые старыми версиями,
открываются новыми. Пустое или чужое состояние отклоняется (проверка сигнатуры).

## Потоки и обмен данными

| Поток | Что делает | Что ему запрещено |
|---|---|---|
| **Аудио** (хост / RtAudio) | `Engine::process`: модули, измерители, кольцо тюнера, применение пресета в момент тишины | аллокации, блокировки, файлы, логирование, JSON |
| **UI / главный** | IGraphics, обработка мыши/клавиатуры, `OnIdle` (таймер iPlug2): завершение загрузки пресета, резервное применение без аудио, пересборка окна при смене масштаба | долгие операции в обработчиках событий |
| **Рабочий поток кабинета** | синтез/загрузка/ресемплинг IR, подготовка разбиений конволвера | — |

Механизмы обмена:

* **Параметры** — атомарные значения `ParamValues`; модули получают их в `update()` в начале блока,
  внутри блока значения сглаживаются (`LinearSmoother`).
* **Порядок цепочки и параллельная секция** — `ChainConfig` публикуется seqlock'ом (двойной буфер + счётчик).
  Аудиопоток применяет новый порядок после короткого затухания (~12 мс), сбрасывает состояния модулей и
  плавно возвращает уровень (ADR-009).
* **Включение модулей** — кроссфейд между обработанным и прямым сигналом, без щелчков.
* **Измерители, GR, корреляция, состояние лупера** — `std::atomic<float/int>` с relaxed-порядком.
* **Тюнер и анализатор EQ** — SPSC-кольца (`SpscRing`) из аудиопотока в UI; анализ (NSDF, FFT) выполняется в UI.
* **IR кабинета** — рабочий поток готовит новый конволвер, аудиопоток переключается атомарно с кроссфейдом
  (`Convolver::promoteSecond`); старый объект освобождается вне аудиопотока.
* **MIDI** — `MidiMap`: lock-free таблица CC → параметр (Learn, канал, диапазон, инверсия); сообщения
  обрабатываются в `ProcessMidiMsg`.
* **Лупер** — команды UI через атомарную ячейку `Looper::command()`, исполняются в начале следующего блока.

## Путь сигнала (`Engine::process`)

1. Выбор входа (`Input Mode`: Left / Right / Sum / Stereo), защита от NaN/Inf, копия «сухого» сигнала для Bypass.
2. `Input Trim`, отвод сигнала в кольцо тюнера и ключ DI для гейта.
3. Цепочка модулей в текущем порядке; при включённой параллельной секции диапазон `[splitStart, splitEnd)`
   обрабатывается двумя путями (A и B, маска `laneB`) и смешивается `Parallel A/B Mix`.
4. Плавная смена порядка цепочки или пресета (затухание → применение → нарастание).
5. `Output Trim`, аварийный потолок +12 dBFS и замена NaN/Inf тишиной.
6. Глобальный Bypass (кроссфейд с сухим сигналом), метроном, Mute тюнера, вывод.

Моно/стерео: блок несёт флаг `stereo`. Цепочка остаётся моно, пока стерео не создаст модуль (панорама
кабинетов, стерео-задержка/реверберация/модуляции, лупер). Так экономится CPU и сохраняется моносовместимость.

## Пресеты

* 60 заводских пресетов описаны в `FactoryPresets.cpp` и встроены в бинарник; уровни выровнены
  (`amp.level`, таблица `levelTrims()` по результатам `tsl_render --calibrate`).
* Пользовательские пресеты — `~/Library/Application Support/TwoonemoonSoundLab/Presets/*.tslpreset` (JSON),
  избранное и недавние — `library.json`, настройки интерфейса — `settings.json`.
* Загрузка пресета: значения готовятся в UI-потоке, аудиопоток применяет их в момент короткого затухания;
  если аудио не идёт 150 мс, пресет применяется из `OnIdle`. Запросы во время перехода ставятся в очередь.
* A/B — два полных снимка; undo/redo — до 100 снимков.

## Интерфейс

* IGraphics на NanoVG + Metal. Базовый размер окна 1200×760; масштабы 75–250% — векторная перерисовка
  с масштабированием разметки, шрифтов и областей нажатия.
* **Компактный режим (50%)** — отдельная раскладка 600×380 в масштабе 1.0 (шрифты нормального размера).
  Переход полный ↔ компактный пересобирает окно в `OnIdle` (вне обработчиков контролов) и синхронизирует
  значения параметров с новыми контролами.
* Страницы: Игра, Пресеты, Цепочка, Усилитель, Кабинет, Эффекты, EQ; служебные — Настройки, Справка;
  оверлеи — тюнер, знакомство. Контекстное меню параметра (правый клик): MIDI Learn, ввод значения, сброс.
* Тексты справки и подсказки — `Source/UI/HelpContent.cpp` (выгрузка: `docs/HELP_CONTENT.md`).

## Задержка (latency)

Все модули основной цепочки имеют нулевую латентность, плагин сообщает хосту 0 сэмплов. Оверсэмплинг на IIR
halfband даёт групповую задержку ~0.13 мс (не чистую задержку). Голоса Pitch/Octave Poly/Harmonizer запаздывают
на 20–40 мс относительно прямого сигнала — это свойство алгоритма, прямой сигнал не задерживается.
Подробности — DSP_DESIGN.md.
